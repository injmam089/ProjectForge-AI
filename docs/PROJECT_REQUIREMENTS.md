# Project Requirements

## Functional requirements
- FR-01: Register, authenticate, log out, and isolate each user's data.
- FR-02: Create and manage projects with name, idea, problem, users, project type, difficulty, technology preferences, and constraints.
- FR-03: Analyze ideas into goals, roles, features, modules, functional/non-functional requirements, architecture, data, API, security, testing, deployment, risks, and roadmap.
- FR-04: Ask clarification questions when missing information materially changes the solution.
- FR-05: Allow review, editing, section regeneration, and validation.
- FR-06: Require explicit user approval before generating documents.
- FR-07: Persist a validated structured Project Specification as the source of truth.
- FR-08: Generate context-relevant Markdown documents.
- FR-09: Preview, edit, save, and regenerate Markdown documents.
- FR-10: Export selected documents as a safe ZIP.
- FR-11: Show project status and history in a dashboard.
- FR-12: Support AI-assisted editing while preserving project consistency.

## Non-functional requirements
Security, maintainability, reliability, responsive UI, accessibility, validation, useful errors, testability, and environment-based secrets.

## States
DRAFT → ANALYZING → REQUIREMENTS_READY → UNDER_REVIEW → APPROVED → GENERATING → GENERATED → EXPORTED.

## Acceptance principle
A feature is done only when implemented, validated, tested where appropriate, and documented.
